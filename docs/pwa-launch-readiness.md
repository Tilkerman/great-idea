# TiLi: готовность к росту (PWA-first)

**Назначение:** один список «косяков и рисков на будущее» — что уже сделано в продукте/коде, что только задумано, что делать до рекламы и до N пользователей.

**Как читать статусы**

| Статус | Смысл |
|--------|--------|
| **Готово** | Уже в коде/проде, менять не обязательно для старта |
| **Частично** | Работает на малых масштабах; при росте нужна доработка |
| **Запланировано** | Решение принято, в коде ещё нет |
| **Риск** | Может сломаться или создать юридическую/репутационную проблему, если игнорировать |
| **Не делаем на этапе PWA** | Сознательно отложено (Play, TG, облачный sync) |

**Этап:** только PWA, проверка спроса. Google Play и Telegram — не считаем.

**Прод:** https://tilkerman.github.io/great-idea/ · Push: Yandex Cloud Function + Object Storage (`cloud/yandex/tili-push/`).

## 1. Много пользователей (общее)

| Тема | Статус | Сейчас | Что может пойти не так | Когда чинить |
|------|--------|--------|------------------------|--------------|
| Данные задач | **Готово** | IndexedDB на устройстве, без нагрузки на сервер | Сервер не падает от 10k пользователей с делами | — |
| GitHub Pages | **Готово** | Статика, CDN | Лимиты Pages редко упираются для PWA | При смене домена — обновить `BASE_PATH`, manifest, CORS push |
| Обязательная регистрация | **Не делаем** | Гость сразу | — | Не вводить до облачного sync |
| Облачный sync | **Не делаем** | Mock auth | Один человек = несколько «учёток» на разных устройствах | После доказанного retention |

## 2. Push-уведомления

| Тема | Статус | Сейчас | Что может пойти не так | Когда чинить |
|------|--------|--------|------------------------|--------------|
| Контур push | **Готово** | VAPID + API в prod-сборке, `subscribe` / `reminders` / `tick` | Нулевой баланс Yandex → push перестанут уходить | Следить за биллингом; пополнить до окончания гранта/баланса |
| UX «сначала настройки» | **Готово** | Первое напоминание → всплывашка; напоминания только при `notificationsEnabled` + permission | Пользователь ждёт push без настроек | — |
| iPhone | **Частично** | Только PWA с «Домой», iOS 16.4+ | Без установки push не будет (не баг) | Лендинг + onboarding текст |
| Android / «любая страна» | **Готово** | Географию TiLi не режет | Системные запреты, убитое приложение без облака | Облако уже есть; держать `tick` по расписанию |
| Время напоминания | **Частично** | `fireAt` считает **телефон** (мс), сервер сравнивает с `Date.now()` | Отдельного IANA timezone на сервере нет; смена пояса/ DST — edge cases | При жалobах или Lumi daily на сервере — хранить `timeZone` |
| Мёртвые подписки | **Готово** | 404/410 → устройство удаляется из `devices.json` | — | Можно логировать count для аналитики |
| **Масштаб push-сервера** | **Риск** | Все устройства в **одном** `devices.json`; каждый запрос read/write whole file; `sendDue` — цикл по всем | ~1000+ активных push: таймаут функции, гонки записи, задержки | **До** массовой рекламы с push: БД/очередь, sharding, idempotent writes |
| Стоимость | **Риск** | Pay-as-you-go Yandex | Рост вызовов `reminders` при каждом открытии app | Мониторинг расхода; лимиты частоты sync |
| CORS push API | **Частично** | `ORIGIN = https://tilkerman.github.io` | Свой домен без правки функции → subscribe fail | При custom domain — обновить CORS + env |
| Юридика UK/EU | **Риск** | Подписки push в Object Storage **РФ** | Реклама в UK/EU без adequacy / DPA | **До** рекламы UK/EU: юрист; опция EU endpoint для подписок |
| product-rules vs prod | **Частично** | В rules ещё может быть «облака нет» | Путаница у разработчиков | Держать rules в sync с этим файлом |

## 3. Языки и реклама

| Тема | Статус | Сейчас | Что может пойти не так | Когда чинить |
|------|--------|--------|------------------------|--------------|
| UI ru / en / es | **Готово** | Каталог i18n, переключатель в настройках | Lumi: не везде es | По мере ES-рекламы |
| Default locale | **Частично** | Default **`ru`**, `index.html lang=ru` | Английская реклама без `?lang=en` → русский UI | **До** EN-кампании |
| `?lang=` в URL | **Запланировано** | Не читается при старте | Рекламная ссылка не попадёт в язык | Первая задача launch: bootstrap locale |
| Приоритет языка | **Запланировано** | Документ: param → user → browser → en | — | Реализовать в одном месте (`AppContext` init) |
| PWA `start_url` | **Риск** | `./` без `?lang=en` | iPhone: **отдельное** хранилище от Safari; язык из Safari не переносится | Manifest `start_url` с lang **или** первый экран выбора языка в standalone |
| Лендинг EN/RU | **Запланировано** | Нет отдельной landing | SEO, доверие, инструкция «Домой» | До платной рекламы |

## 4. Аналитика и приватность

| Тема | Статус | Сейчас | Что может пойти не так | Когда чинить |
|------|--------|--------|------------------------|--------------|
| Сбор содержимого дел | **Готово (не собираем)** | Только локально | — | Никогда на этом этапе |
| Retention / воронки | **Запланировано** | Нет product analytics | Автор не видит 3/7-day return | После выбора PostHog/аналог + consent |
| Лендинг-метрики | **Запланировано** | Нет | Нет UTM/источников | Umami/Plausible на landing |
| Push metrics | **Частично** | `GET health` → count devices; 410 → удаление | Нет дашборда отвалов | Логи функции / cron report |
| Локальная «регистрация» | **Частично** | Mock, сервер не знает | «Сколько зарегались» — только событие в analytics | С event `signup_local` без PII |
| Политика конфиденциальности | **Риск** | Нет актуального текста под трекеры/push cloud | UK/EU реклама | **До** analytics и UK ads |
| Consent GDPR | **Запланировано** | Нет экрана | Нельзя честно считать retention EU без согласия | Решение автора: все vs только EU |

## 6. Пороги «когда что делать» (ориентир)

| Масштаб | Действие |
|---------|----------|
| **0 → первая реклама** | `?lang=en`, landing, privacy, consent analytics, биллинг Yandex, тексты iPhone «Домой» |
| **~100–300 push-устройств** | Смотреть логи `tick`, время выполнения функции, размер `devices.json` |
| **~1000+ push-устройств** | План миграции push-хранилища (не один JSON) |
| **UK/EU реклама** | Юрист + privacy; рассмотреть EU storage подписок |
| **Retention OK** | Тогда Play / optional registration / cloud sync — отдельное решение |

## 7. Открытые решения автора (не код)

- Порог успеха retention (например % на 7-й день).
- Consent analytics: все пользователи или только EU/UK.
- Push storage: оставить RF + юрист или EU replica.
- Выбор: Plausible/Umami + PostHog (условия на момент выбора проверить).
